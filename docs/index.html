Authenticated everywhere

VAULTX04 authenticates the header and every streamed chunk, so tampering fails before it can become data.

RFC 8452 per-chunk tags

A KDF that earns its keep

Argon2id uses 256 MiB, three iterations, and four lanes to make offline guessing expensive in hardware and software.

Argon2id memory-hard

Streaming, not buffering

Files move through 1 MiB chunks. A tiny file and a huge archive follow the same bounded-memory path.

BE32 stream atomic output

Secrets get wiped

Keys and plaintext buffers use Zeroizing<T>, so sensitive memory is cleared as soon as it goes out of scope.

How it works

Four steps between
plain text and protected.

01

Choose a file

Drop it into the app or select it from your device. Encryption and decryption are detected from the file's magic bytes.

02

Set a passphrase

Use a memorable, high-entropy passphrase. The strength meter gives feedback; the passphrase never touches disk.

03

Encrypt locally

The Rust core derives a key, streams the file, authenticates each chunk, and writes a temporary output first.

04

Keep the original

The output becomes a portable .vx2 vault. You can optionally wipe the source after an atomic replacement.

Questions

Asked often.
Answered plainly.

Can I recover my files if I forget the passphrase?

No. There is no backdoor, recovery key, or master password. If the passphrase is lost, the files are gone. That is intentional: a recovery path that lets you in also lets an attacker in.

Is my passphrase stored anywhere?

No. The passphrase is held in memory only long enough to derive the encryption key through Argon2id, then it is wiped. It is never written to disk, sent over a network, or logged.

What is the difference between V2, V3, and V4?

V2 (VAULTX02) is the legacy single-shot format. V3 (VAULTX03) introduced streaming in 1 MiB chunks. V4 (VAULTX04) is the current default and authenticates the header as AAD on every chunk. New files use V4.

Is there a CLI?

Yes. neuron-encrypt-cli supports encrypt, decrypt, scrub, piping, JSON output, password files, and shell completions. It ships alongside the desktop builds and can also be installed from GitLab.

How do I report a vulnerability?

Use the GitLab confidential issue form. Do not post sensitive details in a public issue.
