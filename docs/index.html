Authenticated everywhere

VAULTX04 binds the full header — magic, salt, nonce — as associated data on every 1 MiB chunk. Flip one header byte and decryption fails before a single plaintext byte escapes.

RFC 8452 per-chunk tags BE32 counter

A KDF that earns its keep

Argon2id at 256 MiB × 3 passes × 4 lanes makes GPU farms pay rent for every guess.

RFC 9106 memory-hard

Streaming, not buffering

1 KB or 1 TB follows the same path: ~258 MB flat RAM, 4 PiB ceiling, atomic rename at the end.

1 MiB chunks atomic output

Secrets get wiped

Keys and plaintext live in Zeroizing<T> — cleared from RAM the moment they drop.

How it works

Four steps between
exposed and sealed.

  1. 01

    Choose a file

    Drop it in or browse. Magic-byte sniffing already knows encrypt from decrypt.

  2. 02

    Set a passphrase

    Long and memorable beats short and complex. It lives in RAM only, then is wiped.

  3. 03

    Seal it locally

    Key derived, file streamed in 1 MiB chunks, each chunk authenticated, temp file first.

  4. 04

    Keep the vault

    A portable .vx2 appears. Optionally wipe the original — with confirmation.

Questions

Asked often.
Answered plainly.

Can I recover my files if I forget the passphrase?

No. There is no backdoor, recovery key, or master password. If the passphrase is lost, the files are gone. That is intentional — a recovery path that lets you in also lets an attacker in.

Is my passphrase stored anywhere?

No. It is held in memory only long enough to derive the key through Argon2id, then wiped with Zeroizing. Never written to disk, never sent over a network, never logged.

What is the difference between V2, V3, and V4?

V2 (VAULTX02) is legacy single-shot. V3 (VAULTX03) added 1 MiB streaming. V4 (VAULTX04) is the current default and authenticates the header as AAD on every chunk. All three decrypt; new files use V4.

What does metadata scrubbing actually remove?

EXIF/GPS, XMP, IPTC, ICC, and thumbnails from images; author/dates/XMP from PDFs and Office files; ID3, APE, Vorbis, and RIFF tags from audio; iTunes atoms from MP4. Payloads are copied byte-for-byte. Unknown formats fail closed.

Is there a CLI?

Yes — neuron-encrypt-cli ships with every desktop build: encrypt, decrypt, scrub, pipes, --json, password files, and shell completions.

How does this compare to VeraCrypt or Cryptomator?

Neuron Encrypt is file-level with a misuse-resistant cipher and memory-hard KDF; VeraCrypt is volume-level, Cryptomator targets cloud files. See the comparison table above for the full breakdown.

Why does Windows warn on first install?

Authenticode certificates cost hundreds per year; F-Droid distribution is already live (unsigned build), so Windows signing is the last remaining platform for code signing. Click “Run anyway” — and always verify the SHA-256 hash first.

How do I report a vulnerability?

Use the GitLab confidential issue form. Never post sensitive details in a public issue.
