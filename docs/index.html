What makes it different

🔒

Nonce-misuse resistant

AES-256-GCM-SIV (RFC 8452). Even if nonce reuse happens, your plaintext stays confidential. Per-chunk authentication tags catch any tampering.

🧠

Memory-hard KDF

Argon2id at 256 MiB / 3 iterations / 4 lanes. GPU and ASIC resistant. Offline brute-force becomes prohibitively expensive.

🔀

Streaming, not buffering

Files of any size (up to 4 PiB) stream through 1 MiB chunks. Constant ~258 MB RAM whether you encrypt 1 KB or 1 TB.

🛡️

Authenticated header

V4 format authenticates the full header (magic, salt, nonce) as AAD on every chunk. Any tampering is detected at the AEAD layer.

⚡

Cancel mid-operation

Started encrypting the wrong file? Hit Cancel. The .tmp file is cleaned up and you're back to a clean state in under 50 ms.

🧹

Memory hygiene

Every key, plaintext buffer, and intermediate is wrapped in Zeroizing<T>. Secrets are wiped from RAM the moment they go out of scope.

🌍

Cross-platform

Windows x64, macOS Universal (Intel + Apple Silicon), Linux x64, and Android 7.0+ (arm64, armv7, x86_64, x86). One Rust core, four platforms.

📦

Atomic writes

Output is written to a .tmp file first, then renamed on success. Kill the process, pull the plug — no partial or corrupted files on disk.

🔇

Offline-first Android

Zero internet permissions. Zero storage permissions (uses Storage Access Framework). Your files never leave your device.

How it works

1

Drop a file

Drag any file onto the window, or click Browse. The app auto-detects whether it's a plaintext (encrypt) or .vx2 (decrypt).

2

Enter a passphrase

Type a strong passphrase. The strength meter gives instant feedback. Confirm it (encrypt) or enter the original (decrypt).

3

Click ENCRYPT

The file is encrypted in 1 MiB chunks and written atomically to yourfile.vx2 beside the original. Your original is never modified.

4

Done

Optionally wipe the original (with confirmation). The .vx2 file is self-contained: same passphrase, same app, any platform.

Threat model

Protected against:
  • Offline brute-force (Argon2id 256 MiB)
  • Ciphertext tampering (per-chunk GCM-SIV tags)
  • Header tampering (V4 AAD)
  • Nonce reuse (GCM-SIV is misuse-resistant)
  • Truncation attacks (encrypt_last flag byte)
  • Chunk reordering (counter binding)
  • Plaintext in RAM after use (Zeroizing)
Not protected against:
  • Cold-boot / DMA attacks (no in-memory encryption)
  • Keyloggers and screen recorders
  • SSD wear-leveling (secure wipe is best-effort)
  • Weak passphrases (strength meter is advisory)
  • Metadata (file names, sizes, timestamps)

FAQ

Can I recover my files if I forget the passphrase?

No. There is no backdoor, no recovery key, no master password. If you forget the passphrase, the files are gone. This is by design — a backdoor that lets you in also lets an attacker in.

Is my passphrase stored anywhere?

No. The passphrase is held in memory only long enough to derive the encryption key via Argon2id, then it's zeroed. It's never written to disk, never sent over the network, never logged.

What's the difference between V2, V3, and V4 formats?

V2 (VAULTX02) is the legacy single-shot format — entire file loaded into RAM, ≤1 GiB. V3 (VAULTX03) is the streaming format — 1 MiB chunks, no size limit, but the header is not authenticated. V4 (VAULTX04) is the current default — same as V3 but with the header authenticated as AAD on every chunk. All three are readable by v2.1; new encryptions use V4.

Why is the binary not code-signed?

Code signing requires an Authenticode certificate ($200-400/year for OV, more for EV). This is an open-source project without a budget for that yet. Windows SmartScreen will warn on first install — click "Run anyway". Long-term we plan to obtain a cert. Always verify the SHA-256 hash in the release notes against your download.

Can I use this for full-disk encryption?

No. Neuron Encrypt is a file-level encryption tool, not a disk encryption tool. For full-disk encryption use LUKS (Linux), FileVault (macOS), or BitLocker (Windows). For container-based encryption use VeraCrypt.

Is there a CLI?

Yes. neuron-encrypt-cli ships with the desktop build. It supports piping (encrypt -i file.pdf -o - | ssh ...), JSON output for CI/CD, password files, and shell completions. See the CLI docs.

How do I report a vulnerability?

Do NOT open a public GitHub issue. Use the GitHub Security Advisory to report privately. We'll acknowledge within 48 hours and work with you on a fix before public disclosure.
